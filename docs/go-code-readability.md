# Go 代码可读性规范

## 1. 目标与范围

通过中文契约注释、逻辑空行和清晰的表达式布局，帮助读者快速找到调用边界与处理阶段。

本规范适用于手写 Go 代码。可读性整理保持接口、权限、错误码、数据库条件、排序、审计及返回值等现有行为；函数抽取、文件拆分和业务调整分别评审。

已完成全仓库 203 个 Go 文件的盘点：185 个手写文件完成整理，18 个生成文件保持原样。手写范围包含正式代码、71 个测试文件、历史 POC 和格式工具；混合生成的 Resolver 文件按手写实现区段整理。逐文件清单见 `docs/go-code-readability-audit.md`。

保留的样板入口：

- `packages/go-server-kit/modules/auth/users.go`：公共查询 DTO、筛选构造和用户查询服务。
- `projects/multi-database-demo/internal/graph/admin/users.go`：GraphQL 用户返回值、筛选和排序适配。

写操作与认证入口：

- `packages/go-server-kit/modules/auth/user_mutations.go`：创建用户、批量更新、事务内权限复核及会话撤销。
- `packages/go-server-kit/modules/auth/http.go`：认证路由、来源校验、会话 Cookie 和共享限流。

四空格格式继续由项目 `format-go` 工具统一。格式工具负责缩进和规范化输出，代码作者负责处理阶段、注释内容和表达式布局。

## 2. 声明注释说明调用契约

导出的类型、函数、方法补中文文档注释。复杂私有类型和函数补职责、调用前提及关键返回值说明；简单私有转发和直观转换函数保留简洁代码。

注释以标识符开头，使用完整中文句子，紧贴声明。声明之间留一个空行。信息按实际需要覆盖：

- 用途、参数及返回值的含义。
- `nil`、零值、空数组、显式 `false` 与可空字段的语义。
- 权限、输入限制、错误边界与副作用。
- 事务、并发、取消及资源生命周期的重要约定。

例如：

```go
// GetUser 校验 user:get 权限后，按至少一个有效筛选条件查询用户并记录审计。
// 多条记录匹配时返回 ID 最小的记录；查无记录时返回 nil, nil。
```

类型注释可以集中说明关联字段；具有独立或容易歧义的语义时，在字段旁补说明。字段文档与实现中的限制保持一致，例如字符串按字节计长、筛选集合最多 100 项。

包级文档集中介绍职责、核心 API 和调用约定，多文件包选择一个合适的文件承载。正式应用、公共基础设施、工具与历史 POC 均保留各自的包职责说明。

## 3. 实现注释解释关键原因

函数体内的注释用于解释兼容、安全、并发、数据约定及特殊分支的原因。简单赋值和直观错误检查由代码表达。

用户查询样板中需要保留的解释包括：

- `nil` 集合表示省略，空 `IN` 匹配零条，空 `NOT IN` 跳过对应筛选。
- SQL 字段名与运算符使用固定表，条件值通过占位符绑定。
- `ILIKE` 使用 `LOWER` 与 `LIKE` 表达。
- 业务排序值相同时使用唯一 ID 确定顺序。
- 延迟审计在返回时读取命名返回值 `err` 和最终查询目标。
- GraphQL 相同排序优先级保留固定字段收集顺序。

用户写操作与认证入口中需要保留的解释包括：

- 更新输入通过 `Optional.Set` 和指针区分省略、赋值与显式清空。
- 用户管理先获取初始化单例写锁，再在事务内重新读取操作人与目标，复核最新权限。
- 批量更新最多匹配 100 个用户；角色与封禁变更按现有条件触发会话撤销。
- 创建审计及更新审计在函数返回时记录，读取最终目标与错误。
- Cookie 使用签名、URL 转义及配置的安全属性；Authorization 有值时优先使用该来源。
- 缺少 Origin 时，Cookie 来源的写请求和 WebSocket 升级受到来源门禁约束。
- 请求体上限与单个 JSON 值检查先执行，随后依次校验 IP 桶与账号桶。
- 限流 key 使用 HMAC 派生；Redis 原子计数维护从首次请求开始的 60 秒窗口。

注释密度用于发现待审查区域。验收关注契约准确性与关键原因的解释；新增规则和代码调整时同步审查相关注释。

## 4. 空行按处理阶段组织

- 独立的顶层类型、函数和方法之间留一个空行。
- 函数内部在处理阶段切换时留一个空行，例如审计、权限校验、输入校验、查询准备、数据库执行和结果处理。
- 调用与紧随的错误检查保持相邻，构成完整处理单元。
- 同一阶段中的直接关联语句保持紧凑，循环与其结果整理按职责分组。
- 同一个结构体中可按字段职责分组，组间留一个空行。
- 普通代码块首尾保持紧凑，阶段边界使用一个空行。

例如：

```go
if err = s.Require(ctx, "user", "get"); err != nil {
    return nil, err
}

db, count, err := userWhere(s.db.WithContext(ctx), where)
if err != nil {
    return nil, err
}
if count == 0 {
    return nil, userInput("用户查询需要有效筛选条件")
}
```

长函数先划分完整阶段，并为非直观约定补原因说明。函数抽取和文件拆分结合职责与回归证据另行评估。

## 5. 密集表达式逐项展开

- 多语句单行函数展开为常规函数体；单语句简单函数按清晰度选择布局。
- 较长的条件表、映射表和结构体初始化逐项换行，相关项目保持一致布局。
- 字段赋值展开时保持字段顺序、求值顺序和指针语义。
- 表驱动逻辑保留当前结构，重点让每个条件与对应运算符可直接对应。
- 行宽作为阅读参考，以表达式结构决定换行位置。

例如：

```go
columns := map[string]string{
    "id":        "id",
    "name":      "name",
    "email":     "email",
    "role":      "role",
    "createdAt": "created_at",
    "updatedAt": "updated_at",
}
```

## 6. 生成代码与特殊注释

`generated.go`、`models_gen.go` 等生成文件交给生成工具维护。Resolver 中的手写实现按区段归属整理，涉及重生成时复查手写内容的保留结果。

构建标签、`//go:` 编译及工具指令、`//line` 指令、生成标记和工具约定注释保留其文本、关联位置及作用范围。原始字符串和协议样本中的空白属于数据内容，按原值保留。

## 7. 自动化与分批推广

当前继续使用项目格式工具与现有检查入口。`revive` 的 `exported`、`package-comments` 规则，以及 `wsl_v5` 的空行检查作为候选，后续先在样板包试跑，筛选符合项目习惯的规则，再确定接入方式。

全仓库推广已覆盖认证、店铺、队列、实时通信、基础设施和历史 POC。维护时按业务阶段整理空行，测试代码按数据准备、动作执行和结果断言分段；测试文件的说明概括实际覆盖主题，复杂夹具说明环境与资源归属。

相似实现中的生命周期说明分别核验，例如公共 Bus 借用 Redis 客户端，实时 POC 的 Bus 关闭时释放客户端。长度限制按真实单位说明，新密码使用字节数，实时协议使用 UTF-16 码元，店铺名称数据库校验使用 Unicode 字符数。

## 8. 验收清单

- 声明注释与实际参数、返回值、错误和副作用一致。
- 处理阶段清楚，调用与错误检查保持相邻。
- 普通注释和位置信息移除后，Go AST 保持一致；构建及工具指令单独核对。
- 原始字符串、协议样本、权限、筛选、排序和审计语义保持原值。
- 四空格格式检查通过，新增空行经格式化后保留，重复格式化结果相同。
- Go 回归与项目检查通过；外部数据库或 Redis 条件缺失导致的跳过项目单独记录。

规范命令：

```bash
rtk pnpm format:check
rtk pnpm check
rtk pnpm test
```

局部编辑可使用项目四空格工具仅格式化目标文件；完整整理时使用 `rtk pnpm format`，随后核对改动范围。

独立 POC 与工具 module 使用 `GOWORK=off` 和项目内 Go、GOPATH、GOCACHE。Worker 的外部进程测试通过 `rtk proxy python3 scripts/verify-worker-poc.py` 创建隔离 Redis、双 Worker 及 PID；实时 POC 通过 `rtk proxy python3 scripts/verify-realtime-poc.py` 验证双 Web 和连接生命周期。正式 module 的 Redis 集成测试使用独立测试实例及 `REDIS_TEST_URL`。数据库及外部进程用例按各自环境条件验收，跳过数量与依赖原因单独记录。
