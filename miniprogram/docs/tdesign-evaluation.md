# TDesign 小程序探索结论

日期：2026-10-18，2026-10-19 补充审查修复。范围：相对自建 UI 基线 `1940fdf` 的本轮 TDesign 接入、主题、组件、示例、构建及测试改动。

## 当前决定：采用 TDesign，优先复用官方组件

继续采用固定版本 `tdesign-miniprogram 1.17.0`，通过项目 `src/components/ui/` 入口使用。项目负责排版、布局、语义配色与业务组合，官方组件负责控件视觉、状态及交互。后续按业务需要增加组件，不一次性注册整库。

2026-10-19 用户确认目前基本确定采用 TDesign。后续先查固定小程序发布包是否已有对应能力，再决定项目组合；不继续建立与官方重叠的控件实现。

### 现有 UI 复用排查

本轮直接核对安装的 1.17.0 发布包、组件类型／WXML／样式、项目调用及模板注册。以下为排查结论与本轮收敛结果。

| 范围                                                                                                                  | 当前状态与结论                                                               | 后续处理                                                         |
| --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Button、Input、Switch、CheckboxGroup、RadioGroup、Textarea、Cell/CellGroup、Divider、Tabs/TabPanel、TabBar/TabBarItem | 已使用官方原生组件，主要保留类型、事件、状态保护、间距与主题适配             | 继续透传官方能力，保留已有兼容修复                               |
| 旧 FormField                                                                                                          | 已移除旧组件、专用 Context 和 Input 关联分支                                 | 普通输入用 label/tips；组合字段与统一校验按需接入 Form/FormItem  |
| 页面标题与正文                                                                                                        | 已接入官方 Title/Text/Paragraph，覆盖页面、Card 与 EmptyState                | 保留四档字号，根节点默认外边距归零，间距由父容器管理             |
| Card                                                                                                                  | 只有标题、说明及内容布局；当前小程序包没有 Card                              | 保留精简页面组合，避免用 CellGroup 的列表语义替代任意内容容器    |
| EmptyState                                                                                                            | 已复用 Empty，标题、说明和操作由插槽组合；官方 Empty 没有独立 title 属性     | 保留必要组合；Result 用于操作结果，不能作为空态的直接替代        |
| Tag                                                                                                                   | 原 Badge 已更名为 Tag，使用官方标签组件                                      | 标签使用 Tag；数量徽标保留官方 Badge，例如 TabBarItem.badgeProps |
| 主题与辅助逻辑                                                                                                        | 系统主题、语义配色、tap 事件归一、选择组 readonly 派生均有项目或版本适配职责 | 保留必要适配，不把它们误当作重复实现的控件                       |

Form/FormItem 尚未注册到当前原生模板与 JSX 类型；其父子关系、实例校验／重置方法以及 React 数据回填需贯通验证。函数校验规则等也不能假定可以经普通属性序列化直接传递。Title/Text/Paragraph 已在原生根节点映射四档字号并清零默认 margin，保留实例覆盖与父容器间距；不复制省略、复制及装饰功能。

最初的问题是缺少设计规范。参考 shadcn/ui 自建的方案已建立统一主题和基础样式，但弹层、选择器、选择组、多行输入等控件仍需持续自行实现。TD 已为这些需求提供同一体系的视觉、状态和亮暗主题；现有四档文字、项目主色配置和系统主题机制也可以保留。因此，当前收益足以支持继续采用。

保留建议不等于已完成生产设备验收。当前自动验证覆盖组件适配和构建稳定性；正式发布前仍需完成下文的微信专项。若未来 Taro/TD 升级后适配层持续扩大、关键交互无法稳定通过，重新评估运行时依赖，保留项目主题和组件接口作为退出边界。

## 需要承担的成本

当前 Taro 4.2.1 / Vite 7.1.12 对原生组件的支持存在实际缺口。`config/plugins/tdesign.mjs` 维护相对路径、生成目录、动态图片模板、WXSS、spread 属性、事件绑定、官方主题输出及 watch 原生入口等适配；发布包引用的 tslib/dayjs 也需要显式固定。这些成本集中在构建与包装层，升级时必须复验，不能按普通 React 组件库直接替换版本。

此前白屏由 watch 后公共 chunk 丢失原生组件需要的导出引起，已修复并加入连续重建回归。仅检查文件存在或 Windows 同步一致不足以证明可启动，还必须实际加载组件或核对导出引用。用户已确认该修复后的首页恢复。

本轮导航组件迁移后的生产产物约 1.25 MB（163 个文件、1252373 字节），为目录文件大小合计，不是微信上传压缩包大小，也没有测得同配置下自建基线的体积差。开发构建仍有 Taro 生成路径与公共资源重复输出提示；目前产物完整性验证通过，提示未被屏蔽。

## 本轮全面审查与修复

审查覆盖依赖和锁文件、构建插件、原生注册及 JSX 类型、全部项目组件、主题映射、示例和业务页面适配、测试与规范。确认并修复以下五类问题：

| 问题                          | 修复与回归                                                                     |
| ----------------------------- | ------------------------------------------------------------------------------ |
| 原生模板遗漏无障碍名称        | 显式注册 SuperComponent 在运行时补充的 aria 属性，验证真实 Taro 模板生成绑定   |
| Button 遗漏开放能力事件       | 补实时手机号、服务动态事件的名称映射及模板、回调回归                           |
| Input 的 defaultValue 无效    | 仅初始化一次默认值；受控 value 优先，空字符串能够清空                          |
| Button/Tag 点击参数多嵌套一层 | 将官方自定义事件中的原始 tap 归一到项目 onClick 接口，保留坐标、触摸和事件控制 |
| 自定义危险色状态不完整        | 同步按下、禁用及危险 Tag 浅底；显式官方变量覆盖仍最后生效                      |

主色在 Switch、Radio、Checkbox 的正常选中态本身能够继承品牌变量，没有将其列为缺陷。无障碍模板绑定通过只证明传递链路存在，不代表所有官方控件都消费这些属性，更不代表真实读屏已验收。组件保留了项目使用的 Taro 接口，但不承诺所有平台属性或新原生能力完全等价。

后续微信控制台反馈还确认了第六类适配问题：宿主模板把未传的 openType 等属性直接绑定，微信收到 null，产生类型警告并覆盖官方默认值。当前通过 Taro 官方 mergeThirdPartyComponents 与 WXS 默认值机制补值，保留空字符串、false、0 和非受控 null。

默认值适配曾连续引入两处模板回归：HTML 实体经 Tailwind 的 class 处理解码后破坏属性边界；改用单引号只修复了这一处，用户仍反馈异常。本轮微信原生编译器进一步确认 overlay-props 的空对象三元表达式报 `unexpected token }`。已删除宿主模板的二次改写，空对象交给官方 WXS 的 xs.d()，通过 xs.b() 补缺省值。增加真实编译器的成功和旧表达式失败对照；Node 求值不能替代 WXML 编译。两处回归来自项目适配代码，体现了当前接入成本，页面恢复仍待用户确认。随后附件确认仍有 Button style 类型警告：Taro 对样式的独立分支绕过默认值机制，现于 TD 属性生成处把缺省/null 清空转为空字符串，已有内联样式保留，并验证其他组件不受影响。

2026-10-19 再次审查后的三项 P2 已修复：

- CheckboxGroup 的组 readonly 未向子项传递，RadioGroup 在相同 options 引用下动态开启只读也可能失效。包装统一派生只读选项，解除时恢复原始单项状态，兼容 keys 别名和数值；回归执行官方原生方法与生命周期，验证受控/非受控内部值及事件。
- Input 的 name 来自微信表单行为，原 props.js 注册遗漏。显式补齐表单组件的 name 与字符串默认值，回归贯穿 Input 包装与真实 Taro 模板求值；实际 Form 提交仍待设备验证。
- 自定义 secondary 只改变背景，普通边框与伪元素仍为品牌浅色。现同时映射背景及边框变量，保留显式官方变量优先级，并读取真实官方 WXSS 验证消费关系。

这些缺口说明，项目仍须验证原生状态、行为注入属性及主题状态配对；单凭类型、回调拦截或 JSX 属性存在不足以证明行为正确。修复集中在包装、模板注册及主题适配，固定官方版本保持不变，当前保留 TD 的建议维持。
